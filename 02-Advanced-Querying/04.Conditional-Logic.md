# Conditional Logic

## 🧠 Intuition

Sometimes a query needs to make decisions: bucket prices into "cheap/mid/premium," show a friendly
label instead of a code, pick a fallback when a value is missing, or avoid dividing by zero. SQL's
**`CASE`** expression is the universal if/then/else; **`COALESCE`** and **`NULLIF`** are specialized
shortcuts for NULL handling. These are **standardized** — identical on both engines.

> 💡 **Analogy — a sorting decision tree.** `CASE` is a flowchart embedded in your query: "if the
> price is under 3, label it 'cheap'; else if under 10, 'mid'; otherwise 'premium'." Each row flows
> through and comes out with a label.

## 📐 The tools

| Tool | Does | Portable? |
|------|------|-----------|
| **`CASE`** | General if/then/else, any condition | ✅ both engines |
| **`COALESCE(a, b, ...)`** | First non-NULL argument | ✅ both engines |
| **`NULLIF(a, b)`** | NULL if `a = b`, else `a` (guards divide-by-zero) | ✅ both engines |
| `IIF(cond, a, b)` | Two-way shortcut | 🟦 only |
| `GREATEST/LEAST(a, b, ...)` | Max/min across columns | 🐘 (and 🟦 2022+) |

## 💻 CASE — searched and simple forms

```sql
-- Searched CASE (most common): each WHEN is a full condition
SELECT name, unit_price,
    CASE
        WHEN unit_price < 3  THEN 'cheap'
        WHEN unit_price < 10 THEN 'mid'
        ELSE 'premium'
    END AS price_band
FROM products;

-- Simple CASE: compares one expression to values
SELECT name,
    CASE status
        WHEN 'Shipped'   THEN 'Done'
        WHEN 'Cancelled' THEN 'Void'
        ELSE 'In progress'
    END AS status_label
FROM orders;
```

`CASE` is an **expression** — it produces a value, so it works in `SELECT`, `WHERE`, `ORDER BY`,
`GROUP BY`, aggregates (conditional aggregation), and `HAVING`.

```sql
-- CASE in ORDER BY: custom sort order
SELECT name, status FROM orders
ORDER BY CASE status WHEN 'Pending' THEN 0 WHEN 'Shipped' THEN 1 ELSE 2 END;

-- CASE inside an aggregate (conditional sum)
SELECT SUM(CASE WHEN status = 'Shipped' THEN 1 ELSE 0 END) AS shipped_count FROM orders;
```

## 💻 COALESCE & NULLIF

```sql
-- COALESCE: first non-null — display fallback
SELECT name, COALESCE(city, country, 'Unknown') AS location FROM customers;

-- NULLIF: returns NULL when args are equal — the classic divide-by-zero guard
SELECT revenue / NULLIF(order_count, 0) AS avg_order_value FROM stats;
-- if order_count is 0, NULLIF makes it NULL, and x / NULL = NULL (no error) instead of a crash
```

> `COALESCE` and `CASE` are related: `COALESCE(a, b)` is shorthand for `CASE WHEN a IS NOT NULL THEN
> a ELSE b END`. Both are ANSI standard and portable.

## 🟦 SQL Server vs 🐘 PostgreSQL

| Need | 🟦 SQL Server | 🐘 PostgreSQL |
|------|--------------|---------------|
| If/then/else | `CASE` / `IIF(cond, a, b)` | `CASE` *(no `IIF`)* |
| First non-null | `COALESCE` / `ISNULL` | `COALESCE` *(no `ISNULL`)* |
| Null if equal | `NULLIF` | `NULLIF` |
| Max/min across columns | `GREATEST`/`LEAST` (2022+) | `GREATEST`/`LEAST` |
| Boolean in SELECT | `CASE ... END` (no native bool) | can return `BOOLEAN` directly |

```sql
-- 🟦 IIF shortcut (two-way only)
SELECT name, IIF(units_in_stock > 0, 'In stock', 'Out') AS availability FROM products;
-- 🐘 (and portable): use CASE
SELECT name, CASE WHEN units_in_stock > 0 THEN 'In stock' ELSE 'Out' END AS availability FROM products;
```

> Use **`CASE`** for portable code. `IIF` (🟦) and `ISNULL` (🟦) are convenient but engine-specific;
> `COALESCE`/`NULLIF`/`CASE` work everywhere.

## ⚡ Under the Hood / Performance

- `CASE` evaluates conditions **in order** and **short-circuits** at the first match — put the most
  common/cheapest conditions first.
- A `CASE` (or function) on an **indexed column in `WHERE`** can be non-SARGable and defeat the
  index — see [SARGability](../06-Indexing-and-Performance/05.SARGability.md). Prefer plain range
  predicates where possible.
- `COALESCE` with a subquery argument may evaluate it more than once on some engines; `CASE` lets
  you control evaluation precisely.

## 🚫 Common mistakes

```sql
-- ❌ Missing ELSE → unmatched rows become NULL (sometimes a surprise)
SELECT CASE WHEN unit_price < 3 THEN 'cheap' WHEN unit_price < 10 THEN 'mid' END AS band ...
-- premium products get NULL! ✅ add ELSE 'premium' if you want a value

-- ❌ Comparing to NULL inside CASE WHEN with = (always UNKNOWN → falls to ELSE)
CASE WHEN city = NULL THEN 'unknown' ELSE city END   -- never matches
-- ✅ CASE WHEN city IS NULL THEN 'unknown' ELSE city END

-- ❌ Divide by zero
SELECT total / order_count FROM stats;   -- crashes when order_count = 0
-- ✅ SELECT total / NULLIF(order_count, 0) FROM stats;

-- ❌ Using ISNULL on PostgreSQL
SELECT ISNULL(city, 'n/a') ...   -- ERROR on 🐘
-- ✅ COALESCE(city, 'n/a')
```

## 🌍 Real-World Use

- **Categorization:** price/age/score bands, risk tiers, status labels.
- **Display mapping:** turn codes (`'S'`, `'C'`) into readable text.
- **Safe math:** `NULLIF` divide-by-zero guards in rate/average calculations.
- **Custom sorting:** `CASE` in `ORDER BY` to force a business order ("Pending" before "Shipped").
- **Conditional aggregation:** the `SUM(CASE WHEN ...)` pivot pattern from the previous chapter.

## 🎯 Practice (with full solutions)

### 1. Price bands — `Easy`
**Task:** Label each product `'cheap'` (<$3), `'mid'` (<$10), or `'premium'`.
**Solution:**
```sql
SELECT name, unit_price,
    CASE WHEN unit_price < 3 THEN 'cheap'
         WHEN unit_price < 10 THEN 'mid'
         ELSE 'premium' END AS price_band
FROM products;
```
**Why it works:** searched `CASE` checks conditions top-to-bottom; the `ELSE` catches everything ≥
$10. Portable across both engines.

### 2. Safe average order value — `Medium`
**Task:** Compute average order value as `revenue / order_count`, returning NULL (not an error) when
`order_count` is 0.
**Solution:**
```sql
SELECT revenue / NULLIF(order_count, 0) AS avg_order_value FROM stats;
```
**Why it works:** `NULLIF(order_count, 0)` turns a zero divisor into NULL; dividing by NULL yields
NULL instead of a runtime divide-by-zero error.

### 3. Custom status sort + fallback location — `Medium`
**Task:** List orders sorted `Pending → Shipped → Cancelled`, showing the customer's city or
`'Unknown'` if missing.
**Solution:**
```sql
SELECT o.order_id, COALESCE(c.city, 'Unknown') AS city, o.status
FROM orders o
JOIN customers c ON c.customer_id = o.customer_id
ORDER BY CASE o.status WHEN 'Pending' THEN 0 WHEN 'Shipped' THEN 1 ELSE 2 END,
         o.order_id;
```
**Why it works:** `COALESCE` supplies the fallback location portably; `CASE` in `ORDER BY` imposes
a business-defined order that plain alphabetical sorting couldn't.

## ✅ Key Takeaways

- **`CASE`** is SQL's portable if/then/else — an *expression* usable in `SELECT`, `WHERE`,
  `ORDER BY`, `GROUP BY`, and aggregates.
- **`COALESCE`** = first non-null (portable; prefer over 🟦-only `ISNULL`); **`NULLIF`** guards
  divide-by-zero.
- Always test NULL with `IS NULL` inside `CASE`, never `= NULL`.
- `CASE` short-circuits in order — put common conditions first; avoid wrapping indexed columns in
  `WHERE`.
- 🟦 extras (`IIF`, `ISNULL`) are convenient but non-portable — use `CASE`/`COALESCE` for portability.
