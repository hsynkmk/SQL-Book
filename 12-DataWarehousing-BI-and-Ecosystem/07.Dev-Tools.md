# Dev Tools (the SQL toolbox)

## 🧠 Intuition

You don't write SQL in a vacuum — you use **client tools** to connect, browse schemas, run queries,
read execution plans, and script/load data. SQL Server and PostgreSQL each have a GUI workhorse, a
command-line client, and bulk-load/scripting utilities. Knowing the toolbox makes you fast.

> 💡 **Analogy — a mechanic's bench.** The same job (tighten a bolt) needs different wrenches for
> different cars. The *concepts* — connect, query, inspect plans, bulk-load, script — are identical;
> only the tool names differ between the SQL Server bench (🟦) and the PostgreSQL bench (🐘).

## 📐 The tool categories

| Category | What it does | 🟦 SQL Server | 🐘 PostgreSQL |
|----------|--------------|--------------|---------------|
| **GUI IDE** | browse, query, plans, admin | **SSMS** (Windows), **Azure Data Studio** (cross-platform) | **pgAdmin**, **DBeaver**, **DataGrip** |
| **CLI client** | scripted/interactive queries | **sqlcmd**, `mssql-cli` | **psql** |
| **Bulk load/export** | fast import/export | **bcp**, `BULK INSERT`, `OPENROWSET` | **`COPY`** / `\copy`, `pg_bulkload` |
| **Schema/data scripting** | dump & recreate | SSMS "Generate Scripts", **DACPAC** (SSDT) | **pg_dump** / **pg_restore** |
| **Project/CI dev** | source-controlled DB | **SSDT** (SQL projects, DACPAC) | migrations (Flyway, Liquibase, sqitch) |
| **Cross-platform/extensible** | one tool, many DBs | **Azure Data Studio**, DBeaver, DataGrip | DBeaver, DataGrip |

## 💻 🟦 SQL Server tools

- **SSMS (SQL Server Management Studio)** — the classic full-featured Windows IDE: object explorer,
  query editor, **graphical execution plans**, Activity Monitor, Profiler, agent jobs, backups/
  restores, security — the DBA/dev workhorse.
- **Azure Data Studio (ADS)** — modern, cross-platform (Win/Mac/Linux), VS Code-based, notebooks,
  extensions; great for queries and lightweight admin (less full-featured than SSMS for deep admin).
- **sqlcmd** — command-line T-SQL (scripts, automation, CI). `bcp` — high-speed bulk copy in/out.
- **SSDT (SQL Server Data Tools)** — Visual Studio-based **database projects**: schema as code,
  builds a **DACPAC** for repeatable, comparable deployments (state-based).

```bash
# sqlcmd: run a script
sqlcmd -S localhost -d shop -i script.sql -o out.txt
# bcp: bulk export a table to a file, then import
bcp shop.dbo.products out products.dat -S localhost -T -c
bcp shop.dbo.products in  products.dat -S localhost -T -c
```

## 💻 🐘 PostgreSQL tools

- **psql** — the powerful built-in CLI: run SQL, plus **backslash meta-commands** (`\dt` list tables,
  `\d table` describe, `\l` databases, `\du` roles, `\timing`, `\copy`). The PostgreSQL pro's daily
  driver.
- **pgAdmin** — the official web/desktop GUI: browse, query, plans, admin. **DBeaver** / **DataGrip**
  are popular cross-DB GUIs many prefer.
- **`COPY` / `\copy`** — high-speed bulk load/unload (server-side `COPY` vs client-side `\copy`).
- **pg_dump / pg_restore** — logical backup/scripting (schema and/or data); see
  [Backup & Restore](../11-Operations/01.Backup-and-Restore.md).

```bash
# psql: connect and run a script
psql -h localhost -d shop -f script.sql
# Inside psql: meta-commands
\dt                 -- list tables
\d products         -- describe the products table
\timing on          -- show query timings
\copy products TO 'products.csv' CSV HEADER     -- client-side bulk export
\copy products FROM 'products.csv' CSV HEADER    -- client-side bulk import
```

## 🟦 SQL Server vs 🐘 PostgreSQL — quick map

| You want to… | 🟦 | 🐘 |
|--------------|----|----|
| Full GUI admin | SSMS | pgAdmin / DBeaver |
| Cross-platform GUI | Azure Data Studio / DBeaver | pgAdmin / DBeaver / DataGrip |
| Run scripts from CLI | `sqlcmd -i` | `psql -f` |
| List/describe objects fast | SSMS object explorer | `psql` `\dt`, `\d` |
| Bulk load a file | `bcp` / `BULK INSERT` | `COPY` / `\copy` |
| Dump & restore | Generate Scripts / DACPAC / backup | `pg_dump` / `pg_restore` |
| DB as code (CI/CD) | SSDT + DACPAC (state-based) | Flyway/Liquibase/sqitch (migration-based) |

> Note the philosophy difference for **DB-as-code**: SSDT/DACPAC is **state-based** (declare the
> desired schema; the tool diffs & generates the change), while the PostgreSQL world leans
> **migration-based** (ordered, hand-written change scripts). Both work for either engine via
> third-party tools — covered more in [Application Integration](08.Application-Integration.md).

## ⚖️ Picking tools

- **Deep SQL Server admin** → SSMS. **Cross-platform / notebooks / lighter** → Azure Data Studio.
- **PostgreSQL power use** → `psql` (fastest for pros) + a GUI (pgAdmin/DBeaver) for browsing.
- **One tool for many databases** (mixed 🟦/🐘/MySQL shops) → **DBeaver** or **DataGrip**.
- **Automation/CI** → CLIs (`sqlcmd`/`psql`) + bulk tools (`bcp`/`COPY`) + DB-as-code (DACPAC/Flyway).

## 🚫 Common mistakes

```text
❌ Doing row-by-row INSERTs for a million-row load → glacially slow.
✅ bulk tools: bcp / BULK INSERT (🟦), COPY / \copy (🐘) — orders of magnitude faster.

❌ Clicking schema changes in a GUI on production with no script/source control → unrepeatable, risky.
✅ DB-as-code: DACPAC (🟦) or migrations (🐘) in version control, deployed via CI.

❌ Confusing server-side COPY (needs file on the server) with client-side \copy (file on the client).
✅ use \copy from psql when the file is on your machine.

❌ Using only SSMS and being lost on Mac/Linux → learn Azure Data Studio / DBeaver for portability.
```

## 🌍 Real-World Use

- **🟦 shops:** SSMS for admin/queries/plans, Azure Data Studio for cross-platform/notebooks, `bcp`
  for loads, SSDT/DACPAC for CI/CD schema deployment, `sqlcmd` in automation.
- **🐘 shops:** `psql` for daily work and scripting, pgAdmin/DBeaver for browsing, `COPY` for fast
  loads, `pg_dump`/`pg_restore` for backups/migrations, Flyway/Liquibase for versioned schema.
- **Mixed shops:** DBeaver/DataGrip to use one IDE across all engines.

## 🎯 Practice (with full solutions)

### 1. Fast-load a CSV — `Easy`
**Task:** Load a 5-million-row `products.csv` into the `products` table as fast as possible, on each
engine.
**Solution:**
```bash
# 🟦 SQL Server — bcp (or BULK INSERT / OPENROWSET)
bcp shop.dbo.products in products.csv -S localhost -T -c -t","
#   or T-SQL:  BULK INSERT dbo.products FROM 'products.csv' WITH (FORMAT='CSV', FIRSTROW=2);

# 🐘 PostgreSQL — COPY (server-side) or \copy (client-side)
psql -d shop -c "\copy products FROM 'products.csv' CSV HEADER"
#   or in SQL:  COPY products FROM '/path/products.csv' CSV HEADER;   (file must be on the server)
```
**Why it works:** bulk-load paths (`bcp`/`BULK INSERT` and `COPY`/`\copy`) stream rows in a single
optimized operation — minimal logging/overhead — vs millions of individual `INSERT`s, making them
orders of magnitude faster for big loads.

### 2. Inspect a table from the CLI — `Easy`
**Task:** From a terminal (no GUI), list the tables and see the `products` table's columns/indexes.
**Solution:**
```bash
# 🐘 PostgreSQL — psql meta-commands
psql -d shop -c "\dt"        # list tables
psql -d shop -c "\d products" # columns, types, indexes, constraints

# 🟦 SQL Server — sqlcmd querying catalog views
sqlcmd -S localhost -d shop -Q "SELECT name FROM sys.tables;"
sqlcmd -S localhost -d shop -Q "SELECT c.name, t.name AS type FROM sys.columns c
   JOIN sys.types t ON t.user_type_id=c.user_type_id WHERE object_id=OBJECT_ID('dbo.products');"
```
**Why it works:** 🐘's `psql` has rich built-in `\d` meta-commands for instant introspection; 🟦
achieves the same via **catalog/system views** (`sys.tables`, `sys.columns`) queried with `sqlcmd` —
both let you explore schema without a GUI.

## ✅ Key Takeaways

- Every category has a 🟦 and 🐘 equivalent: **GUI** (SSMS / Azure Data Studio vs pgAdmin / DBeaver),
  **CLI** (sqlcmd vs **psql**), **bulk load** (**bcp**/`BULK INSERT` vs **`COPY`**/`\copy`),
  **dump/restore** (DACPAC/Generate Scripts vs **pg_dump/pg_restore**).
- **psql** meta-commands (`\dt`, `\d`, `\timing`, `\copy`) make the PostgreSQL CLI extremely
  productive; SQL Server introspects via **catalog views** (`sys.*`).
- Use **bulk tools** for big loads (never row-by-row), and **DB-as-code** for schema changes —
  **state-based** (DACPAC) on 🟦 vs **migration-based** (Flyway/Liquibase) commonly on 🐘.
- **DBeaver/DataGrip** give one IDE across both engines for mixed shops.
