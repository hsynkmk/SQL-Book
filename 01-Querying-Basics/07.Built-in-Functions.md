# Built-in Functions

> **The single biggest area of dialect divergence.** SQL Server and PostgreSQL name and shape their
> string, date, and conversion functions very differently. This is your translation table.

## 🧠 Intuition

Built-in functions transform values: uppercase a name, extract the year from a date, round a
number, replace NULL with a default, convert a string to a date. The *concepts* are universal —
every database can uppercase text — but the **function names and signatures differ a lot** between
engines. Knowing the map is what makes you portable.

> 💡 **Analogy — the same tool, different brand names.** Both a SQL Server and a PostgreSQL toolbox
> have a "get the year out of a date" tool. One is stamped `YEAR()`, the other `EXTRACT(YEAR ...)`.
> Same job, different label.

## 📐 String functions

| Need | 🟦 SQL Server | 🐘 PostgreSQL |
|------|--------------|---------------|
| Length | `LEN(s)` *(trims trailing spaces!)* | `LENGTH(s)` / `char_length(s)` |
| Upper / lower | `UPPER(s)` / `LOWER(s)` | `UPPER(s)` / `LOWER(s)` |
| Substring | `SUBSTRING(s, start, len)` | `SUBSTRING(s, start, len)` / `substr()` |
| Concatenate | `s1 + s2` *(or `CONCAT`)* | `s1 || s2` *(or `CONCAT`)* |
| Concat (null-safe) | `CONCAT(a, b)` | `CONCAT(a, b)` |
| Replace | `REPLACE(s, from, to)` | `REPLACE(s, from, to)` |
| Trim | `TRIM(s)` / `LTRIM` / `RTRIM` | `TRIM(s)` / `LTRIM` / `RTRIM` |
| Find position | `CHARINDEX(needle, s)` | `POSITION(needle IN s)` / `strpos(s, needle)` |
| Left / right | `LEFT(s, n)` / `RIGHT(s, n)` | `LEFT(s, n)` / `RIGHT(s, n)` |
| Pad | `' '` manual / `FORMAT` | `LPAD(s, n, c)` / `RPAD(s, n, c)` |
| Split to rows | `STRING_SPLIT(s, ',')` | `string_to_array` / `regexp_split_to_table` / `unnest` |
| Aggregate to string | `STRING_AGG(s, ', ')` | `string_agg(s, ', ')` |

```sql
-- Concatenate first and last name
-- 🟦 SQL Server
SELECT first_name + ' ' + last_name AS full_name FROM employees;   -- but NULL + x = NULL!
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM employees;  -- null-safe
-- 🐘 PostgreSQL
SELECT first_name || ' ' || last_name AS full_name FROM employees;
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM employees;  -- null-safe
```

> ⚠️ **`+` (🟦) and `||` (🐘) propagate NULL**: `'A' + NULL = NULL`. **`CONCAT()` treats NULL as
> empty string** on both engines — use it when any argument might be NULL. Also: 🟦 `LEN` ignores
> trailing spaces, while 🐘 `LENGTH` counts them — a subtle gotcha.

## 📐 Date & time functions

| Need | 🟦 SQL Server | 🐘 PostgreSQL |
|------|--------------|---------------|
| Now (local / UTC) | `GETDATE()` / `SYSUTCDATETIME()` | `now()` / `now() AT TIME ZONE 'UTC'` |
| Today (date) | `CAST(GETDATE() AS DATE)` | `CURRENT_DATE` |
| Extract part | `YEAR(d)`, `MONTH(d)`, `DAY(d)`, `DATEPART(hour, d)` | `EXTRACT(YEAR FROM d)`, `date_part('hour', d)` |
| Add interval | `DATEADD(day, 7, d)` | `d + INTERVAL '7 days'` |
| Difference | `DATEDIFF(day, d1, d2)` | `d2 - d1` *(returns an `interval`/int)* |
| Truncate to unit | `DATETRUNC(month, d)` *(SQL 2022+)* | `date_trunc('month', d)` |
| Format as string | `FORMAT(d, 'yyyy-MM-dd')` | `to_char(d, 'YYYY-MM-DD')` |
| Parse string to date | `CAST('2025-01-01' AS DATE)` / `TRY_CONVERT` | `CAST('2025-01-01' AS DATE)` / `to_date(...)` |

```sql
-- Orders from the last 30 days
-- 🟦 SQL Server
SELECT * FROM orders WHERE order_date >= DATEADD(day, -30, CAST(GETDATE() AS DATE));
-- 🐘 PostgreSQL
SELECT * FROM orders WHERE order_date >= CURRENT_DATE - INTERVAL '30 days';

-- Group orders by month
-- 🟦 SQL Server
SELECT DATETRUNC(month, order_date) AS mth, COUNT(*) FROM orders GROUP BY DATETRUNC(month, order_date);
-- 🐘 PostgreSQL
SELECT date_trunc('month', order_date) AS mth, COUNT(*) FROM orders GROUP BY date_trunc('month', order_date);
```

> ⚠️ Wrapping a column in a function in `WHERE` (e.g. `WHERE YEAR(order_date) = 2025`) usually
> **defeats the index** — it's non-SARGable. Prefer a range: `order_date >= '2025-01-01' AND
> order_date < '2026-01-01'`. See [SARGability](../06-Indexing-and-Performance/05.SARGability.md).

## 📐 Numeric & conversion functions

| Need | 🟦 SQL Server | 🐘 PostgreSQL |
|------|--------------|---------------|
| Round | `ROUND(n, 2)` | `ROUND(n, 2)` |
| Ceiling / floor | `CEILING(n)` / `FLOOR(n)` | `CEIL(n)` / `FLOOR(n)` |
| Absolute / power / mod | `ABS`, `POWER`, `n % m` | `ABS`, `POWER`/`^`, `MOD(n,m)` / `n % m` |
| Cast type | `CAST(x AS INT)` / `CONVERT(INT, x)` | `CAST(x AS INT)` / `x::INT` |
| Safe cast (no error) | `TRY_CAST` / `TRY_CONVERT` | *(no direct equivalent — validate first)* |
| Null fallback | `ISNULL(x, 0)` / `COALESCE` | `COALESCE(x, 0)` |
| Conditional | `IIF(cond, a, b)` / `CASE` | `CASE` *(no `IIF`)* |

```sql
-- Cast a string to int
-- 🟦 SQL Server
SELECT CAST('42' AS INT), CONVERT(INT, '42'), TRY_CAST('oops' AS INT);  -- TRY_CAST → NULL, no error
-- 🐘 PostgreSQL
SELECT CAST('42' AS INT), '42'::INT;     -- '::' is PG's cast shorthand
```

> 🟦's **`TRY_CAST`/`TRY_CONVERT`** return `NULL` instead of erroring on bad input — very handy and
> with **no direct 🐘 equivalent** (in Postgres you validate with a regex or handle the exception in
> PL/pgSQL). 🐘's **`::`** cast shorthand (`'42'::INT`) has no 🟦 equivalent.

## ⚖️ Portability strategy

- Prefer the **standard functions** that exist on both: `COALESCE`, `NULLIF`, `CAST`, `CASE`,
  `SUBSTRING`, `UPPER`/`LOWER`, `EXTRACT`, `TRIM`, `CONCAT`.
- Avoid engine-only shortcuts in portable code: 🟦 `ISNULL`/`IIF`/`TRY_CAST`/`+`-concat;
  🐘 `::`-cast/`||`-concat (though `||` is ANSI-ish, 🟦 doesn't support it for strings).
- When writing for a *specific* engine, use its idioms — they're often cleaner (🐘 `||`, 🟦 `IIF`).

## 🚫 Common mistakes

```sql
-- ❌ NULL-propagating concatenation
SELECT first_name + ' ' + last_name FROM employees;   -- whole thing NULL if either is NULL (🟦)
-- ✅ CONCAT treats NULL as ''
SELECT CONCAT(first_name, ' ', last_name) FROM employees;

-- ❌ Function on an indexed column in WHERE → non-SARGable, full scan
WHERE YEAR(order_date) = 2025;
-- ✅ range predicate uses the index
WHERE order_date >= '2025-01-01' AND order_date < '2026-01-01';

-- ❌ Assuming ISNULL works on PostgreSQL (it doesn't)
SELECT ISNULL(city, 'n/a') FROM customers;   -- ERROR on 🐘
-- ✅ COALESCE works on both
SELECT COALESCE(city, 'n/a') FROM customers;
```

## 🌍 Real-World Use

Formatting names and addresses, bucketing events by month, computing ages and durations, cleaning
imported data (`TRIM`, `REPLACE`), building search keys (`LOWER`), and safely parsing user input
(`TRY_CAST`). The dialect map here is something you'll reference constantly when porting queries
between engines.

## 🎯 Practice (with full solutions)

### 1. Full names, null-safe — `Easy`
**Task:** Produce `full_name` from `first_name` + `last_name`, working even if one is NULL, on both
engines.
**Solution:**
```sql
-- both engines
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM employees;
```
**Why it works:** `CONCAT` is portable and treats NULL as empty — no surprise NULL results.

### 2. Last 7 days of orders — `Medium`
**Task:** Orders placed in the last 7 days, in both dialects, index-friendly.
**Solution:**
```sql
-- 🟦 SQL Server
SELECT * FROM orders WHERE order_date >= DATEADD(day, -7, CAST(GETDATE() AS DATE));
-- 🐘 PostgreSQL
SELECT * FROM orders WHERE order_date >= CURRENT_DATE - INTERVAL '7 days';
```
**Why it works:** a range predicate on the raw `order_date` column stays SARGable (can use an
index); the date math differs only in syntax.

### 3. Monthly order counts — `Medium`
**Task:** Count orders per calendar month.
**Solution:**
```sql
-- 🟦 SQL Server
SELECT DATETRUNC(month, order_date) AS month, COUNT(*) AS orders
FROM orders GROUP BY DATETRUNC(month, order_date) ORDER BY month;
-- 🐘 PostgreSQL
SELECT date_trunc('month', order_date) AS month, COUNT(*) AS orders
FROM orders GROUP BY date_trunc('month', order_date) ORDER BY month;
```
**Why it works:** truncating to the month gives one bucket per month; both engines have a
`*trunc` function, just named differently.

## ✅ Key Takeaways

- Function **concepts** are universal but **names/signatures differ a lot** between engines — this
  page is the translation map.
- **`CONCAT`** is null-safe and portable; `+`(🟦)/`||`(🐘) propagate NULL.
- Date math: 🟦 `DATEADD`/`DATEDIFF`/`YEAR()` vs 🐘 `INTERVAL`/subtraction/`EXTRACT`.
- Casting: portable `CAST`; 🟦 adds `CONVERT`/`TRY_CAST`, 🐘 adds `::`.
- Prefer **standard functions** (`COALESCE`, `CAST`, `CASE`, `EXTRACT`) for portable code; avoid
  wrapping indexed columns in functions inside `WHERE`.
